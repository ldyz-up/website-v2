# 官网内容后台 · 本地预览版

开发分支：`feat/content-admin-preview`。基于远程 `main` 的 `52c3129992eeb2fdd536af01eb94ff5520f8cedd`；保留远程9月28日的询盘和活页夹更新。未合并主分支，未修改 Pages 设置，未发布正式站。

## 打开与操作

- 后台：<http://127.0.0.1:8268/admin/>
- 网站：<http://127.0.0.1:8268/>
- 进入后台，点击“登录”即可使用本地代理；这一版没有接入 GitHub 在线登录，不需要输入 GitHub 密码。
- “首页与页面文字”：选择页面，展开要修改的语言或页面图片。
- “产品管理”：选择现有产品，或点击“创建产品类型的内容”；可修改六种语言的名称和介绍、分类、主图、细节图片、显示开关和展示顺序。编号使用小写字母、数字和短横线，保存后保持编号稳定。
- “公司资料与二维码”：修改公司文案、联系方式、Logo 和二维码。
- 顶部“媒体”进入上传图库。旧网页图片已填在各位置，上传的新图保存在 `uploads/`。替换图片应使用新文件名，不覆盖共用的旧原图；暂不迁入本地的大型原始素材库。
- 修改后点击“保存到本地预览”，再选择同名菜单项。看到“内容已保存”后，切换到网站并刷新，即可检查结果。
- 关闭“在网站上显示”可隐藏产品；数字越小排序越靠前。“删除内容”会移除该分支目录中的对应产品资料，操作前会确认。

## 启动与停止

本机已安装依赖时，双击同目录 `启动后台预览.command`。终端显示两个地址后即可访问；关闭服务时，在该终端按 `Control+C`。若提示端口占用，通常表示预览已经运行，不要重复启动。

在其他开发环境首次安装：使用 Node.js 20 或更新版本，运行 `pnpm install --frozen-lockfile --ignore-scripts`，再运行 `pnpm dev`。Node、pnpm 也可以使用 Codex 提供的依赖运行时。依赖安装在本目录中，不需要全局安装。

预览网站监听 `127.0.0.1:8268`，官方 Decap 文件代理监听 `127.0.0.1:8081`，都仅供本机使用。

## 保存在哪里

内容写入本分支目录中的 `content/pages/`、`content/company.json`、`content/products/`；图片进入 `uploads/`。不是只存在浏览器里的临时数据，关闭浏览器、重启服务后仍保留。

官网预览每次请求都会从这些文件生成内容。`pnpm build:content` 可生成静态网页使用的 `content/managed-data.js`；后续如要正式发布，必须接入正式构建和授权流程，不应只把这次的本地后台直接搬到正式站。

当前后台保存**不会自动提交 Git，也不会推送 GitHub**；本次开发成果由助手单独提交到预览分支。你后续试用时的保存会留在本地开发目录，之后再按需要提交。

## 预览环境边界

- 当前8267主版本保持原位，仍是日常维护主版本；本目录只供这次分支开发和预览。
- 预览页带有明确标识；已拦截表单提交、外部数据请求和表单跳转，避免发送真实询盘邮件。原有询盘源码与 Worker 配置保留，供后续正式接入使用。
- Decap 本地代理是文件系统模式，不支持正式草稿审核；“已保存（本地预览）”不表示已上线。
- 完整网页预览与编辑栏的内容预览分别展示，保存后刷新网页检查完整效果。
- 自动翻译、GitHub 在线登录、草稿分支审核、正式发布、本地自动同步均不属于当前预览接入范围。
